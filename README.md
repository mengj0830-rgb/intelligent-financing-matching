# 程序小库

> 一个个人程序收藏库：以桌面小工具为主，兼收 Web 小玩具、可视化实验、方案文档与设计规范。
> 多数项目**完全离线、开箱即用**，目标是"自己用着顺手，也方便回看当时的实现"。

**作者：** mengj0830-rgb

---

## 这是什么

这里不是单一产品，而是一个长期积累的**程序合集**。每个项目一个独立文件夹，代码、素材、文档、打包脚本都在自己的目录里，互不干扰。技术选型上偏"轻量、离线、零后端"：桌面程序用 Python + PySide6 / pygame，小工具尽量纯前端单文件实现。

本仓库是清理后的**源码版**：打包产物（`dist/`）、虚拟环境、模型权重、个人数据与含密钥的配置均已排除，只保留可版本管理的源码、文档和资源。

## 技术栈速览

- **语言**：Python 3.13、HTML / CSS / JavaScript
- **GUI**：PySide6（业务型桌面应用）、pygame-ce（可视化）
- **打包**：PyInstaller 6.x，统一 onedir 模式（本机环境不适合 onefile）
- **数据**：SQLite / JSON，本地存储
- **图表 / 可视化**：纯代码绘制，尽量零外部运行时依赖

## 快速开始

各项目相互独立，进入对应目录即可运行。以桌面应用为例：

```bash
cd <项目目录>
pip install -r requirements.txt   # 若项目提供依赖清单
python main.py                    # 源码运行
python main.py --smoke            # 多数项目支持自检，退出码 0 = 通过
```

打包（以 onedir 模式产出 `dist/`）：

```bash
python build.py
```

> 打包后的 exe 需与同目录运行环境一起保留，单独拷贝 exe 无法运行——这是 Python 打包程序的正常形态。

## 仓库约定

1. **一程序一目录**：新程序在 `小程序制作/` 下新建同名文件夹，代码、素材、文档都放进去，不混放。
2. **可版本管理优先**：打包产物、虚拟环境、缓存、模型权重、个人数据、含密钥配置一律不入库（见根目录 `.gitignore`）。
3. **配置留模板不留密钥**：需要密钥的项目提供 `config.example.json` / `.env.example`，真实配置由使用者本地创建。
4. **文档留痕**：每个项目尽量保留一份说明文档（功能、用法、技术栈），便于日后回顾。

## 数据与安全

本仓库的源码版本**不含任何个人数据**：`user_data/`、聊天备份、模型权重、`config.json` / `store.json` 等均已在整理阶段剔除并由 `.gitignore` 持续忽略。桌面应用运行时会把数据写在项目目录或用户数据目录，**首次启动会自动创建**，不影响使用。
